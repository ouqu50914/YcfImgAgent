## 实测：GPT2.6 / GPT2.6 pro 真实生图（00:31–00:33，6/6 通过）
- 方式：临时脚本 `/tmp/ycf-model-test.ts` 直接调用项目 `AceGptImage2Adapter.generateImage()`（真实打 `api.acedata.cloud/openai/images/generations`），截获落盘 buffer 到 `/tmp`，**跳过 COS / 数据库 / 积分扣费**；两个模型并发、每个模型 3 个用例串行，总耗时 97s。上游按 Token 计费，本次产生真实费用。
- 用例与结果（全部成功）：
  | 模型（上游） | PNG 1024x1024 | GIF auto → 512x512 / 9 帧 | GIF 1024x1024 / 2 帧 |
  |---|---|---|---|
  | GPT2.6 `gpt-image-2.6-flare:official` | 成功 22.8s，1024x1024 PNG | 成功 25.0s | 成功 16.7s |
  | GPT2.6 pro `gpt-image-2.6-sunburst:official` | 成功 31.0s，1024x1024 PNG | 成功 35.0s | 成功 31.0s |
- 严格 GIF89a 块解析（`/tmp/ycf_gif_parse.py`，不依赖 PIL/ffmpeg）：4 个 GIF 的**实际画布尺寸、帧数、每帧时长、循环信息全部与请求一致** —— 512x512 为 9 帧、1024x1024 为 2 帧、每帧 200ms、infinite loop。
- 结论：① **证实文档「512 只是省略/auto 时的默认预设」**，显式传 1024x1024 上游照单接受并按该尺寸出图（用户上一轮的质疑成立）；② 2.6 pro(sunburst) 的 GIF 与静态图均可用；③ 同步模式无需 `async: true`；④ `frame_count` / `frame_duration_ms` / 尺寸透传 / `.gif` 落盘全链路有效。
- 踩坑记录：手写 GIF 解析器最初把 Image Descriptor 的 `0x2C` marker 字节漏算（应 `off += 10` = marker 1 + 字段 9），导致偏移错位误报坏块；修正后结果稳定。用 `21 F9` 简单计数会把压缩数据误判成帧，**必须按块结构数 `0x2C` Image Descriptor**。
